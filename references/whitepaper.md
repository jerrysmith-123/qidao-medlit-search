# 白皮书生成规范

把"检索 + 溯源 + 证据分级 + 引用核验"成果合成为一份正式白皮书。白皮书的核心要求：**通俗层可读，权威层可考，每条关键论断回退到一手出处。**

## 适用与触发

用户要求"白皮书 / 正式报告 / 体系文档 / 权威综述"时启用；也可由溯源报告 / 证据摘要按本节升级而来。

## 白皮书结构

1. **封面与摘要**：标题、版本号、日期、摘要（含大白话总览）。
2. **核心结论**：先给结论（通俗层），每条附证据等级 + 信源档位 + 出处。
3. **体系框架**：按炁道四层（理论/机制/实践/证据）组织主体内容。
4. **概念溯源**（如涉核心概念）：版本、谱系、时间线。
5. **证据分级总表**：全部关键论断列表，含等级、信源、链接/篇目页码、核验状态。
6. **证据缺口与待考项**：明确列出未达强证据、无法回退一手出处的节点。
7. **参考文献**：按"已查证·一手 / 据转述 / 待考"分类排列。
8. **方法论与免责声明**：说明检索范围、分级标准、验证方式与局限。

## 权威性硬性要求

- **正文准入**：每条关键论断必须 `已查证·信源A`（一手可回退）。`信源B` 转述可作支撑但注明；`信源C` 禁入正文。
- **古籍引用**：书名+篇名+版本+页码，否则标"待考"，不入正文。
- **措辞**：强证据用"经验证/支持"；弱证据用"有助于/据现有证据提示"；不用"治愈/根治/证实"。
- **缺口必须透明**：无法核实的节点列在"证据缺口"，不隐藏、不臆断。
- **版本控制**：每个白皮书标注版本号与生成日期；内容更新即升版本。

## 双层表达

- **通俗层**：每章开头给"大白话结论 + 证据等级通俗释义"，配图形化链路。
- **权威层**：同一内容附严格出处、版本、谱系，独立标注，不混为一谈。

## 交付形态

按用户指定交付（HTML / Word / 飞书 / Markdown）。HTML 适合正式发布，Word/飞书适合协作编辑，Markdown 适合版本管理（可入 Git）。

## 白皮书→Git 联动

白皮书为 Markdown 时，可与技能同仓版本管理；重要版本同步到公开仓库，便于跨设备与归档。
